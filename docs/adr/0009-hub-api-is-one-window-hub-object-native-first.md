# The Hub API is one `window.hub` object, native features first

The Hub preload exposes the whole **Hub API** to a **Plugin UI** as one frozen `window.hub` object, built with `contextBridge` and split into namespaces: `displayLanguage`, `identity`, `backend`, `files`, `stores`, `ai` and `busy`. Calls are async. Read-only facts (`displayLanguage`, `identity`) are plain values fixed for the Plugin's open lifetime. Whatever the platform already does is left out of the Hub API: `fetch` (CORS applies), `navigator.clipboard`, `<input type=file>`, drag-drop, `<a download>` (routed to a native save dialog), `<a target=_blank>` to an `https` URL (opened in the system browser), `visibilitychange` and `pagehide`. The manifest gains no new declarations. A namespace whose existing declaration is missing is absent rather than stubbed: there is no `hub.identity` unless the Plugin needs identity, no `hub.backend` without a Backend, and `hub.stores` rejects store names the Plugin did not declare.

We chose one global object over a Hub-served ES module or several globals because it works the same with any UI framework or none (ADR 0006). We chose to add only what the platform cannot do, because every Hub API call is frozen until the next major version, while native features cost nothing to keep. We chose not to add declarations such as `ai`, `files` or `network`, because Plugins are trusted (ADR 0003) and a declaration that gates nothing is just one more field to validate. We gave the Plugin UI a JSON-RPC client rather than ADR 0003's raw `MessagePort`, so that no Plugin has to rewrite the framing, id matching or error mapping.

## Consequences

- **Versioning.** A Hub implements one major Hub API version and every minor below it. There are no shims for older majors and no version field at runtime, because the `hubApi` range check (ADR 0005) already guarantees the minimum. Types come from a types-only npm package whose version equals the Hub API version. It declares `window.hub` and the Hub Kit elements.
- **`hub.backend`** offers `request(method, params)`, `notify(method, params)` and `onNotification(method, handler)`. Only the Plugin UI sends requests; the Backend may only send notifications, such as progress. Requests queue in the preload until the Backend's `initialize` succeeds.
- **Backend start.** The Hub's first message to a Backend is a JSON-RPC `initialize` request carrying `{dataDir, stores: {name: path}, hubApi}`, and the Python SDK exposes it as a typed context. It carries no Display Language (ADR 0007). If `initialize` fails, or does not answer within a fixed timeout (a named constant, around 10 s), the Plugin closes as if it had crashed (ADR 0003). A Backend still has no other way to call the Hub.
- **`hub.files`** offers `pickFolder(title)`, which returns `{kind: 'chosen', path} | {kind: 'cancelled'}`, and `openFolder(path)`, which reveals a folder in Explorer or Finder. The Backend does the I/O on picked paths. `pickFiles` and similar calls join only when a Plugin needs them.
- **`hub.stores`** offers `list(store, dir)`, `readText`/`readBytes`, `writeText`/`writeBytes` (an atomic replace where the last writer wins, ADR 0008), `remove`, and `watch(store, handler)`, which returns an unsubscribe function and sends recursive, debounced `{path, kind: 'changed' | 'removed'}` events. Paths are relative and POSIX-style. Subfolders are allowed. `..` and absolute paths are rejected.
- **`hub.ai`** offers `providers()`, which returns `[{label, kind, models}]`, and `chat({model, system, messages})`, where `model` is `{kind: 'default'} | {kind: 'chosen', provider, model}` and messages hold text parts plus image parts where the model supports them. It returns `{text: AsyncIterable<string>, done: Promise<string>, cancel()}`, because `contextBridge` cannot carry an `AbortSignal`. There is no tool calling (ADR 0001), no structured output, no reasoning stream and no fallback when the chosen provider is missing. There is also still no way to send to or pre-fill the Assistant Panel.
- **`hub.identity`** is `{id, name, email, roles}`, captured at open. If the Sign-in Lifetime runs out while the Plugin is open, the Plugin stays open, and the next open checks again.
- **`hub.busy`** offers `set(reason)` and `clear()`. The Plugin translates the reason itself, and the Hub shows it when staff close the Plugin or quit the Hub.
- **Errors.** Every rejection is a `HubError` whose `code` belongs to a closed union, such as `'store-not-declared'`, `'provider-missing'` or `'backend-error'`. A Backend's JSON-RPC error passes through under `rpc`.
- **Closing.** The Hub closes the view without waiting on `beforeunload`. Only the Backend gets `shutdown`, and Busy is what protects work in progress.
- Each future addition is a minor bump: `hub.fetch` when a UI-only Plugin hits CORS, more file pickers, structured output.
