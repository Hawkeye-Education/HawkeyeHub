# The Hub owns all styling; Plugins compose a Hub-served kit

Plugins add function, and the **Hub** owns every visual. The Hub draws all **Hub Chrome** (frame, title bar, Plugin switcher, Assistant Panel, dialogs, sign-in, settings) in one window. A Plugin owns only its **Plugin UI** rectangle, cannot open windows of its own (`window.open` is denied) and cannot add to the chrome. Into every Plugin UI the Hub preload loads, before plugin code runs, three things the Hub serves itself: `--hub-*` design tokens (CSS custom properties for colour, type, spacing, radius, elevation, glass and motion), a stylesheet that styles native HTML elements with those tokens, and the **Hub Kit**, a small set of web components whose Shadow DOM keeps plugin CSS out. Plugins may use any UI framework or none, compose from native elements and the Hub Kit, and write layout-only CSS, never their own colour, font, radius, shadow or glass.

We chose a web-components kit over a React kit because it leaves Plugins free to use any framework, and over declarative UI (Plugins describe screens as data, the Hub renders them) because that reverses ADR 0003's "the Plugin UI is the Plugin's own web content" and cannot express a map or a file explorer. We chose a Hub-served kit over an npm package bundled into each Plugin Package, because bundled copies freeze each Plugin at the look it was built with, while a served one always matches the installed Hub and the active **Theme**. We made Themes configurable rather than fixing one Hawkeye look, so the look can change without touching any Plugin.

## Consequences

- A **Theme** is a named set of values for the token interface, holding both light and dark values. Themes are built into the Hub, Hawkeye first; adding one is a Hub release. The Company Configuration names the default Theme, and staff can switch on their installation. Plugins never ship or choose a Theme.
- The **Colour Scheme** (System, Light or Dark) is a separate setting mapped to Electron's `nativeTheme.themeSource`, which drives `prefers-color-scheme` in every `WebContentsView`. Theme and Colour Scheme changes apply live, with no reload and no Hub API call. Backends never see either.
- Token names and Hub Kit elements and attributes are **Hub API**: adding one is a minor bump, renaming or removing one is a major bump. Token values, including any redesign of a Theme, are not API.
- The token interface ([#19](https://github.com/Hawkeye-Education/HawkeyeHub/issues/19)):
  - **Colour:** `--hub-color-canvas`, `-surface`, `-surface-raised`, `-fg`, `-fg-muted`, `-line`, `-accent`, `-on-accent`, `-focus`, `-success`, `-warning`, `-danger`.
  - **Type:** `--hub-font-body`, `--hub-font-mono`, `--hub-text-sm`, `-md`, `-lg`, `-xl`, `--hub-leading`, `--hub-weight-strong`.
  - **Spacing:** `--hub-space-1` to `--hub-space-6`. **Radius:** `--hub-radius-1` to `--hub-radius-3`. **Elevation:** `--hub-shadow-1`, `--hub-shadow-2`.
  - **Glass:** `--hub-glass-fill`, `--hub-glass-blur`, `--hub-glass-edge`. **Motion:** `--hub-motion-fast`, `--hub-motion-slow`, `--hub-motion-ease`, all zeroed or neutral when the OS asks for reduced motion.
- The native-element stylesheet has one hook, also Hub API: `<button data-variant="primary">` marks a screen's main action. Every other button is styled as secondary.
- A Theme may carry fonts. The Hub bundles them and serves them offline; Plugins never load fonts.
- The **Hawkeye** Theme is "Frosted": OS window material behind the whole window, translucent surfaces, Inter + Noto Sans TC (bundled, about 12.8 MB as TTF, shipped as woff2), calm motion. Its values live in Theme A of the [theme prototype](https://github.com/Hawkeye-Education/HawkeyeHub/blob/prototype/hawkeye-theme/prototypes/hawkeye-theme/hub.css). The logo orange `#FF6B35` is used only for the logo mark: under white text it fails WCAG AA (2.84:1), so the accent is `#C2410C` in light and `#FF8A5C` in dark.
- "No windows of its own" binds the Plugin UI. A headed browser a Backend launches through Playwright, for example so staff can sign in to a site, shows a website rather than Plugin visuals and is allowed ([#18](https://github.com/Hawkeye-Education/HawkeyeHub/issues/18)).
- The TS SDK package carries types for the Hub Kit only, never its code. The manifest declares nothing about styling.
- "Layout-only CSS" is enforced by the plugin development standard and code review, not technically: Plugins are trusted (ADR 0003) and CSP cannot tell layout CSS from colour CSS.
- The Hub Kit starts with only what the reference plugin (PDF Watermark Eraser) needs. A widget joins it when a second Plugin needs one; until then a Plugin builds it from native elements and tokens. The Hub Chrome is built from the same tokens and Hub Kit.
- Glass cannot cross views: each Plugin UI is its own `WebContentsView`, so CSS `backdrop-filter` blurs only within one view. Window-wide glass needs the OS window material (`vibrancy` on macOS, `backgroundMaterial` on Windows 11 22H2+ only); Windows 10 has neither, so there glass is dropped and the window gets the Theme's solid tint instead. The Hub picks material or tint once at startup from the OS (`vibrancy` on macOS, `backgroundMaterial: 'acrylic'` on Windows 11 22H2+), and gives every `WebContentsView` a transparent background so the material shows through a Theme whose `--hub-color-canvas` is transparent, as Hawkeye's is.
