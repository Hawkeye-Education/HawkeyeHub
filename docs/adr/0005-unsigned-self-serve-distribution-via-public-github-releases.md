# Unsigned, self-serve distribution with the Registry on public GitHub Releases

Staff install the **Hub** themselves, per user and without admin rights, on `win32-x64` and `darwin-arm64`. The Hub is built with electron-builder and is **not code-signed**. On Windows it is an NSIS per-user installer updated by `electron-updater`. On macOS it is an ad-hoc-signed zip: the first install is a `curl` + unzip one-liner into `~/Applications`, and the Hub then updates itself by downloading the next zip with Node and swapping its own bundle through a detached script, because Squirrel.Mac refuses unsigned apps. The **Registry** is GitHub Releases on the public `Hawkeye-Education/HawkeyeHub` repo. A rolling `registry` release holds `index.json`, the **Company Configuration** (`company-config.json`) and the Hub's update feed, while every Plugin version (`plugin/<id>@<version>`) and Hub version (`hub@<version>`) gets its own release, published by CI on a tag push. Integrity is a `sha256` per artifact in the index, checked over HTTPS, with no signatures.

We chose this over paying for signing (Apple Developer Program at US$99/year for Developer ID and notarization, plus Azure Artifact Signing at US$9.99/month), because there is no budget for it. Unsigned costs one SmartScreen "Run anyway" on first Windows install and a Hub-written updater on macOS. It works only because files the Hub, `curl` and uv write carry no quarantine flag or Mark of the Web, so Gatekeeper and SmartScreen never re-check updates, Plugins or Python runtimes. We chose public GitHub Releases over a private bucket or server because the repo, and with it all Plugin code, is already public. It needs no server, no download token and no new account, and the soft gate (ADR 0002) already accepts that anyone can copy a Plugin. We dropped package signatures because anyone able to tamper with the Registry can push to the repo and reach a CI signing key too.

## Consequences

- **Smart App Control** in enforcement mode on Windows 11 blocks the unsigned Hub and the PBS `python.exe` outright. This assumes no staff machine runs it.
- Upgrade paths, when there is money: Apple Developer ID lets macOS use stock `electron-updater` and retires the self-swap script. SignPath Foundation (free for OSI-licensed public repos built by CI) or Azure Artifact Signing removes the SmartScreen prompt.
- The Company Configuration is public. That reveals the LDAP host, OIDC issuer and directory group names but no credentials, since LDAP binds as the staff member and OIDC is a public PKCE client. The Hub re-fetches it on every Registry check, so changing the Role Mapping needs no rebuild.
- There is no hard gate. A static public Registry cannot check a Staff Identity, so adding one means moving the Registry behind a server as a new effort.
- A **Plugin Package** is one platform-neutral zip per version holding `manifest.json`, `icon.svg`, the Plugin UI build in `ui/`, and optionally `backend/` (Python source, `pyproject.toml`, `uv.lock`) and the Assistant's `agents/` folder (`assistant.md` plus `skills/`; ADRs 0004, 0010). Wheels are never vendored. Supported Platforms gates install instead of per-arch artifacts.
- Install runs in this order: Supported Platforms, then identity and Roles, then the **Hub API** range. The Hub then downloads the Plugin Package, checks its `sha256`, unpacks it and runs `uv python install` + `uv sync`. uv is not bundled: the Hub pins a uv version and a `sha256` per platform, and downloads uv from Astral's GitHub the first time a Plugin with a Python Backend is installed (amended by ADR 0011). PBS comes from Astral's GitHub and wheels from PyPI, pinned by `uv.lock`, with no mirror unless a proxy forces one through uv's env vars. Everything lives in the per-user app data folder, with the uv cache on the same disk so wheels are hardlinked or cloned.
- Each Plugin declares a required `hubApi` semver range. The Hub installs the newest version whose range it satisfies. A Hub update that leaves an installed Plugin behind leaves it installed but unopenable until a compatible version is published.
- Plugin updates are silent. The Hub checks at launch and every few hours. A new version is unpacked and its venv built side by side, then swapped in only on success, and only while the Plugin is closed. A failed build keeps the old version. Staff cannot pin or roll back; developers publish a newer version instead. An unreachable Registry stops only installs and updates.
- Uninstall removes the code and venv and keeps the Plugin's data unless staff opt in to deleting it. It also deletes PBS interpreters no remaining venv uses and runs `uv cache prune`, and removing the last Python-Backend Plugin deletes uv itself (ADR 0011).
