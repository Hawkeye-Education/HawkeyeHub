# Diagnostics stay on the machine until staff export them; no crash reporter, no telemetry

The Hub records what goes wrong in local log files and sends nothing anywhere. When something breaks, staff click **Export diagnostics** (in Hub settings, in the dialog shown when a Plugin crashes, or when the Hub Chrome keeps crashing) and get a **Diagnostics Bundle**, a zip from a native save dialog that they send to whoever maintains the Hub. The Hub collects every log itself, so Plugins need no logging API: a Plugin UI uses `console` and a Backend writes to stderr, as before (ADRs 0003, 0009). There is no usage telemetry of any kind, local or remote.

We chose a staff-exported bundle over Electron `crashReporter` or Sentry because both need somewhere to upload to. The Hub has no backend (ADRs 0002, 0005), and adding a collector, its DSN in the Company Configuration and a privacy review for one internal team is more than support at this size needs. A bundle also never leaves without staff knowing. We chose Hub-side capture over a `hub.log` namespace because every Hub API call is frozen until the next major version, while `console` and stderr already exist. We kept no native minidumps because they hold raw process memory, such as keys and file contents, and are useless without a symbol server.

## Consequences

- **What is captured.** The Hub main process logs its own lifecycle (open, close, install, update, sign-in result), Backend spawn and exit, `initialize` failures, AI Provider call failures (provider label and HTTP status only) and its uncaught exceptions. A Plugin UI's `console.log`, `info`, `warn` and `error` are taken from `webContents`' `console-message` event, which includes uncaught errors and unhandled rejections, and `console.debug` is dropped. A Backend's stderr is kept verbatim, line by line. The JSON-RPC relay records each error response as method, `data.reason` and message, with no params or results. A crash records the `render-process-gone` reason and exit code, or the Backend's exit code or signal, plus its last ~50 stderr lines.
- **Where it lives.** `app.getPath('logs')`, per OS user (ADR 0008): `hub.log` and one `plugins/<plugin-id>.log` per Plugin, which interleaves its Plugin UI and Backend. Each line is JSON: `{time, source: 'hub' | 'ui' | 'backend', level, pluginId, pluginVersion, message}`. Backend lines have `level: 'stderr'` because the Hub does not parse what it did not write. Each file rolls at 5 MB and keeps one previous file. There is no time-based retention. Uninstall with "also delete my data" removes the Plugin's log, and "keep data" keeps it.
- **What is never logged.** The Hub's own log never holds credentials or tokens, AI keys, AI prompts or replies, Assistant conversations, file contents or Staff Identity (a signed-in yes/no is allowed). File and folder paths are allowed, even though they contain the OS username. Plugin logs are written verbatim with no redaction. The Plugin Standard forbids Plugins from logging secrets, file contents or identity.
- **The Diagnostics Bundle.** `hawkeye-hub-diagnostics-<yyyymmdd-hhmmss>.zip` holds every `hub.log*` and `plugins/*.log*` plus `system.json`: Hub version, OS name, version and arch, Display Language, Theme and Colour Scheme, installed Plugins and versions, installed Python interpreter versions, each AI Provider's label and kind (no key), the Auth Provider kind, and whether staff are signed in. It never holds Plugin Data, Shared Stores, secrets or Staff Identity. Export always takes everything: there is no per-Plugin export and no in-Hub log viewer. The Company Configuration gains no support contact.
- **When a Plugin crashes** (ADR 0003), the Hub Chrome shows "**<Plugin name> stopped unexpectedly**" with a plain cause, one of *crashed*, *failed to start* (spawn or `initialize` failed or timed out, ADR 0009) or *stopped responding* (the Plugin UI's `webContents` fires `unresponsive` and does not fire `responsive` within a grace period of about 30 s; a Plugin that recovers within it is left alone, [#21](https://github.com/Hawkeye-Education/HawkeyeHub/issues/21)), and two buttons: **Export diagnostics** and **OK**. Nothing restarts, and there is no Reopen button.
- **When the Hub crashes**, an uncaught main-process exception is logged and the Hub quits. A crashed Hub Chrome renderer is logged and its window reloads, up to 3 crashes within 60 s whatever the `render-process-gone` reason. On the third the Hub stops reloading, logs that it gave up, shows a native "**Hawkeye Hub stopped unexpectedly**" box (the Hub Chrome cannot draw one) with **Export diagnostics** and **Quit**, then quits normally ([#41](https://github.com/Hawkeye-Education/HawkeyeHub/issues/41)). There is no clean-exit marker and no "the Hub crashed last time" prompt on the next start.
- Installed Hubs give Plugin UIs no DevTools. Dev mode keeps them and also prints each Backend's stderr to the terminal.
- If support load ever justifies remote crash reporting, it comes back as its own effort, with a collector and a privacy review.
