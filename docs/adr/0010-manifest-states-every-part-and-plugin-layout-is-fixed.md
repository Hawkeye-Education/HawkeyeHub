# The Manifest states every part, and the Plugin layout is fixed by convention

Written by the PDF Watermark Eraser prototype ([#13](https://github.com/Hawkeye-Education/HawkeyeHub/issues/13), branch `prototype/pdf-watermark-eraser`). Every **Manifest** field is required, and the Manifest is typed: a JSON Schema with a closed enum for every `kind` and for `platforms`, no extra keys, and a matching `Manifest` type in the types package. Editors and packaging validate against that one schema. A part a Plugin may lack is a `kind` union stated explicitly: `identity` is `{kind: 'none'}` or `{kind: 'required', roles}`, `backend` is `{kind: 'none'}` or `{kind: 'python', python: '3.12'}`, and `assistant` is `{kind: 'none'}` or `{kind: 'enabled', templates}`. Next to those sit `id`, `version`, `hubApi`, `name`, `description` (each a string or a Display Language map, ADR 0007), `platforms` and `stores`. Files are at fixed paths, not declared: `icon.svg`, `ui/index.html`, `backend/main.py` (run as a script by the venv's Python), `agents/assistant.md` and `agents/skills/<name>/SKILL.md`. The `agents/` folder is everything the Hub's AI layer (Vercel AI SDK, ADR 0001) reads, and nothing outside it ever reaches a model. Every Plugin ships a required `icon.svg` drawn in one colour with `currentColor`, so the Hub tints it for the active Theme and Colour Scheme. There is still no `permissions`, `locales` or `theme` field, because ADRs 0006, 0007 and 0009 rule each one out.

We chose explicit unions over optional fields because a missing key and a misspelt one look the same. Our coding standard also allows no optional or default leniency at the Manifest boundary, and the Hub API already uses `{kind}` unions (ADR 0009). We chose convention over declared entry paths because every Plugin then reads alike, and packaging checks a fixed list of paths rather than validating free ones. We grouped the Assistant's files under `agents/`, rather than putting `skills/` at the root in the Agent Plugins layout, so the boundary of what an AI provider can see is one folder. A Playbook still opens in any Agent Skills client by pointing it at `agents/skills/`. A Plugin that builds its UI puts the build output in `ui/`. We chose a single-colour icon over a full-colour one so that ADR 0006's "the Hub owns every visual" holds for the Plugin switcher and the Registry too.

## Consequences

- **Hub Kit v1** is `<hub-folder-field>` (a label, the chosen path, a Hub-translated "Browse…" button that calls `hub.files.pickFolder`, firing `change`) and `<hub-log>` (`append({tone: 'info' | 'success' | 'danger', text})`, `clear()`, auto-scrolling). Everything else the reference Plugin needs is a native element. The log exists because plugin CSS may not set colour (ADR 0006), and success or failure needs colour.
- Cancelling a long Backend request uses a Plugin-defined notification (the eraser's `cancel`), not a Hub API feature. A standard `$/cancelRequest` with a cancellable request handle is a later minor bump, added when a second Plugin needs one.
- A Backend rejects requests with JSON-RPC errors carrying a `data.reason` code that the Plugin UI translates, because a Backend has no Display Language (ADR 0007). Technical detail, such as an exception message, may stay in English.
- `backend.python` and `requires-python` in `backend/pyproject.toml` must agree, and packaging checks it.
- The Python SDK runs each request on its own thread and each notification inline on the reader thread, so a notification such as `cancel` reaches a Backend busy with a long request.
- `hub.files.pickFolder` opens Electron's `dialog.showOpenDialog` from the main process, modal to the Hub window. A Plugin UI cannot reach `dialog` itself. `pickFiles` will wrap the same call when a Plugin needs it.
- ADRs 0004 and 0005 are amended to match: the Playbook lives at `agents/skills/`, and the system prompt at `agents/assistant.md`.
